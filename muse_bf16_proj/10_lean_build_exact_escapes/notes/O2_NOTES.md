- Transferable facts (measured here; details in the iterations):
  1. Rare code paths are expensive after the judge's 512 MB flush: instructions are fetched cold from DRAM by the few
     warps that take the path (escape handling inside consumer warps cost 1-2 us per affected CTA). Keep corrections in
     always-executed, branch-free code or in a dedicated warp.
  2. ptxas re-materializes kernel params from the constant bank at their use: an `asm volatile("" : "+l"(p.out))` at
     kernel start does not keep the value in a register; the late LDC/ULDC then misses (cold param line, ~0.4 us).
     An early real use (prefetch / store through the pointer) warms the line.
  3. A helper warp sharing SMSP 0 with 4 busy consumer warps gets ~1/5 of the issue slots: ~100 instructions per event
     on that warp made the final barrier wait ~1 us (ncu: 16 % of samples on the barrier).
  4. Global atomic-counter (dynamic) work distribution for a 12.6 MB stream loses to static stage-major items
     (4.0-6.0 vs 3.7-3.8 local): the atomic round trip per item is on the critical path.
  5. K's m=256 / Q2's m=128 kernels: the first stage lands ~1.2 us after its issue regardless of issue order (W before
     x, sync-first prologue, delaying the later stages); not a DRAM-queue effect.
  6. ncu `-k regex:... -c 1` profiles the FIRST matching launch, which can be a prepare() self-test of another shape:
     use exact kernel names (my first b32 / l32 rows had captured the o16 self-test).

## iteration 2 — ox v1 (ox.py): full-residency persistent kernel for m = 9..32
Design: 128 CTAs x (16 consumer warps + 1 producer warp), CTA = 64 W rows x full K, F12 12-bit W (agent G's format) as
4 stage-major 24 KB bulk items (all issued at t=0), x by 3D TMA (128B swizzle), mma.sync m16n8k16 (W as A decoded from
LDS words, x^T as B via ldmatrix), warps = RG row groups x KS k-splits, k-split partials reduced through smem (aliasing
the ring), exact escape corrections (N's form) from smem x by the producer warp.
- correct on the first build (normal / outliers / one-hot, m 9, 16, 17, 31, 32).
- v1 (x as one 64 KB copy, escape list copied last): m16 5.52 vs 4.29, m32 6.62-6.88 vs 4.62. Timeline (clock64):
  x lands 2.16 us, items 2.2 / 2.95 / 3.5 / 3.9, producer escape pass done at 5.29 (escape list landed last behind
  160 KB in the per-SM TMA FIFO + 32-way bank conflicts on the correction planes); no-compute ablation 6.51.
- v2 (escape list first, x split per item and issued W0, x0, W1, x1, ... (V2's x-lag), per-item escape pass, padded
  corrections): m16 4.94 vs 4.38, m32 5.15-5.25 vs 4.78.
- v3 (producer issues only, escapes in the consumer warps: ballot over the CTA's escape list per item, fake term
  cancelled in the accumulator, x*true via smem float atomics): m32 8.3, m16 6.0 with some CTAs 2-3 us late. Ablations:
  escape pass skipped -> 5.04 (m32); the accumulator update alone +1.4 us. Cause: the escape code is RARE, BRANCHY code:
  the few warps that take it fetch its instructions cold (the 512 MB flush evicts code from L2) -> ~1-2 us per CTA with
  a hit. RULE: no rarely-executed code paths in these kernels (also: smem float atomicAdd is a CAS loop).
- ptxas rematerializes kernel params at their use: `asm volatile("" : "+l"(p.out))` at kernel start does NOT keep the
  value; the LDC c[0x0][0x2c0] moved into the final store loop and missed (cold param line). Fix: an early use that
  cannot be removed (prefetch / early st.global by tid 0 of its own output word, which also loads the global-memory
  descriptor c[0x0][0x208] and the output page translation).
- v4 (producer warp, lane = token, accumulates escapes per escape-row slot in registers via a 16-slot select, one
  write of the correction planes at the end): consumers' main loop normal (items land 2.1 / 2.6 / 3.3 / 3.7, loop end
  4.1) but kernel end 5.6 mean / 6.6 max: ncu SASS sampling: 16 % of all samples are consumers stalled at the final
  barrier waiting for the producer: the producer shares SMSP 0 with 4 busy consumer warps and spent ~100 instructions
  per escape (+100 for the final write). With the escape pass off: end 4.67 mean, 5.06 max, bench 5.07-5.09 (m32).
- v5: producer computes only per-escape products into per-escape slots (~12 instructions, no RMW, no select); the
  reduce adds them with a fixed-length predicated loop (E2 = max escapes per row pair, compile-time, always executed).
- v5 result (box 1): m32 5.76 vs bo11 4.83 (+0.9); producer stall gone (bar1 4.38 = loop end + 0.14) but the
  post-loop phase is still ~1.0 us: k-split partial exchange 0.36 us (KS 4: 32 KB STS + 32 KB LDS per CTA = ~500 clk
  of smem bandwidth) + escape adds / stores 0.67 us; ncu sampling of that region: imc_miss on the late p.M ULDC and
  no_instruction (cold epilogue code).
