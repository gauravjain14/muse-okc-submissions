# Agent R4 — router at m = 128 / 256 (phase 2, base claude/t3/bo11.py), notes

Deliverable: `claude/t3/R4/rt4.py` (`prepare_rt4(weights)`, `run_rt4(x, config, state)` -> out or None; generated by
`mk_rt4.py` from the lab module `r4lab.py`), `sub_rt4.py` (bo11 + rt4), `sub_rt4t.py` (rt4 + torch elsewhere, fast).
Lab: `r4lab.py` (kernel family + options), `t_r4.py` (correctness + globaltimer timelines), `t_rk.py` (same timeline
for agent Y's rk port = bo11's router kernels), `probe_red.py` (reduction-path costs), `ncu_r4.sh` (NVTX-filtered ncu,
Y's script + K's tensor-pipe metrics), `sub_l*.py` (variant candidates).
Base router kernels in bo11: m=128 Y's NVRTC rk port, K split 16 (grid 128); m=256 alygg77's rk, K split 8.
All times local us (claude/bench.py graph replay after a 512 MB flush, empty graph subtracted; judge ~= local + 1.0).

## Current routes (rt4 v1)
- 97 <= m <= 128: r4 (64 W rows x 64 tokens x 512 k, S = 16), 193 <= m <= 256: r4 (64 x 64 x 1024 k, S = 8); grid
  128 compute CTAs + 4 zeroing CTAs. Other m: None (bo11).
- Kernel r4: A = x tile (64 tokens, 2D TMA, 128B swizzle); B = [hi 64 rows ; lo 64 rows] stacked in N: ONE
  wgmma m64n128k16 per k16 step (x read once for hi and lo; hi + lo partials summed in registers at the end, exact for
  one-hot rows because hi + lo is exact in fp32). W packed at prepare into 16 KB 128B-swizzled stage images (one 1D bulk
  copy per stage; K's WPK idea), packed-W address baked into the code (runtime-zero trick). Ring of 8 x 24 KB stages
  (m=128: all 8 k-blocks resident, no slot reuse). 4 zeroing CTAs (blockIdx 0-3, Y's ya scheme) clear out and release
  a counter; compute CTAs' helper warp acquires it. Fast prologue: stage 0's barrier + W + x copies issued before the
  remaining barrier inits. Epilogue: hi+lo add, stage [64 tok][64+4] fp32 in smem, line-coalesced red.add.v4.f32
  (rk's pattern: each warp instruction covers 2 token rows x 256 B).

## Measured facts (this machine)
- Reduction paths (probe_red.py, 128 CTAs each pushing P bytes of fp32 partials; contention = 128 P / O):
  red.add.v4 / plain st.v4 / cp.reduce.async.bulk (1-16 KB chunks) / DSMEM st.async to the cluster partner all cost
  about the same per byte: P = 8 KB 0.3-0.5 us, 16 KB 0.8-1.0, 32 KB 1.4-2.0 (cold output lines); with the output
  L2-resident the increments are the same (~+0.5 us per +8..16 KB). => ~25-30 GB/s per SM (~16 B/clk) of outgoing
  partial data on every path; atomics and bulk reduce are not slower than plain stores; contention 32-way adds ~+0.3-0.5.
- In-kernel (t_r4.py traces, 64 x 128 tiles, S = 32, m=128): 32 KB of red.add per CTA takes 1.3-1.6 us after the zero
  barrier (32-way contention) vs 0.4-0.5 us for 16 KB 16-way (64 x 64 tiles). Bench ~= max "reds issued" + 0.3-0.5 us.
- Helper-warp zeroing (rk scheme): the helper's red.release.gpu completes only when the SM's TMA flood has landed
  (zero release at 3.1-3.3 us at m=128, i.e. with the last stage) -> zero barrier on the critical path (+0.17-0.5 us).
  Dedicated zeroing CTAs (Y's ya scheme) release at 1.7-2.5 us (their stores are acked behind the flood, but early
  enough). Zeroing CTAs placed first (blockIdx 0-3) beat placed last (m=128 5.17 vs 5.24, m=256 5.93 vs 6.14).
- Uncoalesced red epilogue (straight from the wgmma fragments: each warp instruction 16 token rows x 32 B) vs
  smem-staged line-coalesced (2 rows x 256 B per instruction): m=128 5.17 -> 4.94, m=256 5.93 -> 5.87.
- Bulk-copy issue is slow: thread 0 issuing 8 stages (W bulk + x TMA each) finishes at 0.9-1.1 us after kernel start.
- Fast prologue (stage 0 copies before the other barrier inits): m=128 4.84 -> 4.64, m=256 5.67 -> 5.60 (same run).
  Issuing all W stages before any x: much worse (5.66 / 6.26); x-then-W per stage = W-then-x.
- Tile geometry (stream end = last stage landed, trace, m=128): 64 x 128 tiles (L2->SM 16.8 MB) 3.33 us, 64 x 64 tiles
  (25.2 MB) 3.67-4.10 us, rk 3.58. But 64 x 128 doubles the per-CTA partial (32 KB) -> loses (6.09 vs 4.84).
- Cluster launches: K-pair DSMEM reduce-scatter (64 x 128 tiles, S = 32 pairs) m=128 6.08 / m=256 8.04 (placement +
  push 0.34 us + reds); W multicast across token-tile pairs (64 x 64, m=128) with a GPC-aware unit permutation measured
  at prepare (Q2's method): last stage 4.01 vs 3.75 non-cluster (the cluster barrier before the multicast issue + slow
  multicast issue delay the W stream; without the permutation 4.61). Dead ends.
- Phase-ordered 64 x 128 tile (warpgroup 0's x with W first, warpgroup 1's x last, so WG0's reds overlap the stream):
  5.68-5.90 vs 4.93: WG0's reds (16 KB) did not hide (0.7 us after its zero barrier) and delayed the stream. Dead end.

## iteration 9-10 — r4c: W stages in agent Y's lossless 24-bit hi/lo code format, decoded in smem (dead end)
- Format (pack_c): per value hi low byte + lo low byte + 4-bit hi code (sign | e7 - 54) + 4-bit lo code (sign | hi e7 - 4 -
  lo e7); stage image = 12 KB codes (thread-major 16-B segments, conflict-free LDS) + 256-B trailer (per-thread escape
  flag bits, count, (pos, hi bits, lo bits) entries; escapes = hi exponent outside [108, 123], lo == 0, delta outside
  [0, 7]; ~350 per weight set, max 27 per stage). Escapes are patched in smem with the exact bits -> bit-identical tiles
  (t_r4 dense checks pass, rel err 2.5e-6 like raw).
- v1 of r4c (one warpgroup decodes 64 values / thread, then proxy fence + barrier + wgmma): m=128 6.32, m=256 10.27 vs
  raw 4.54 / 5.62. Breakdown (same run): no proxy fence 6.24 / 10.04; no decode at all (24-bit bytes, sync skeleton only)
  4.27 / 5.23 (the byte saving is real: -0.27 / -0.39); no escape scan 5.73 / 8.63 (the scan loop alone cost 0.6 / 1.6 us
  -> per-thread flag bits in v2).
- v2 of r4c (two decoder warpgroups, 32 values / thread, triple-buffered BF16 tiles, decode of stage i+1 overlapping
  wgmma i, separate decoder / MMA loops so ptxas does not serialize the wgmmas): trace m=256 last stage 8.2 us (raw 5.3).
  ncu (NVTX-filtered, flushed):

## Why not more (measured bounds for this design family)
- m=128: stream DRAM-bound (10.5 MB, last stage at ~3.4-3.75 us vs ~3.0 floor); fixed tail ~1.0-1.2 us = last-stage MMA
  0.25-0.35 (tensor lags at the end) + staging/zero barrier ~0.17 + 16 KB of reds per SM ~0.4 + red drain ~0.3. Any tile
  with less L2->SM traffic (64 x 128: stream -0.4 us) doubles the per-SM partial (32 KB) and every exchange path (reds,
  bulk reduce, DSMEM, phase-overlap) costs ~0.04 us/KB/SM.
- m=256: 64 x 64 x 1024 tiles move 50 MB L2->SM (~96 GB/s per SM, 384 KB each); 64 x 128 tiles end the stream 0.8 us
  earlier but again double the partial; cluster multicast / DSMEM variants lose to placement + cluster sync costs.
  Cluster sizes > 2 are not co-resident at 128 CTAs (cluster 4: 30, 8: 15, 16: 7), so on-chip full-K reductions are
  impossible at these tile counts.
